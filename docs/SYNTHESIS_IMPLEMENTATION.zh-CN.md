# 模型与方法融合：Agent 实现路线

日期：2026-10-23。总蓝图和来源库统一保存在 [q-one-core](https://github.com/aidless/q-one-core/blob/main/docs/SYNTHESIS_BLUEPRINT.zh-CN.md)。[29条来源矩阵](https://github.com/aidless/q-one-core/blob/main/literature/MATRIX.zh-CN.md)记录采用候选与限制。以下全部是待实现路线，当前运行接口仅包含本地成本启发式。

## 1. 两种模型角色

Laya 与 Jev 已分别核查原始仓库和官方文档（S01、S02）。它们的类型化结果适合局部问题：某条材料是否相关、该选哪个工具、是否应升级人工。复杂方案生成由可替换的语言模型负责（S03、S04）。角色可分别替换，统一由核心协议记录。

规划的 `ProviderResult` 应增加任务类型、类别概率、模型/权重revision、schema版本、截断状态与失败原因。`success_probability` 只接收明确目标事件的预测，不能直接拿分类置信度填充。当前启发式返回的固定confidence仅为示例，未校准。

## 3. 真实模型回执

每次运行保存 `run_id`、输入摘要或私有文件哈希、来源ID、模型revision、schema/prompt/策略版本、开始结束时间、原始响应的私有定位、解析结果、错误、弃权、实际费用（未知则为空）。公开仓库只收匿名或合成样例。下载成功、mock成功、一次推理成功和任务验收成功分别记录。

Laya代码已固定核查到 `0a05a45052e23ae0b887a490fe8d6d9c8cff2ab5`。这不表示已下载或运行其权重。Jev服务条款与当前API版本需在实际接入时复核；本轮没有调用或计费。

## 4. 比较方案

比较规则基线、Laya、单个生成模型和混合流程，统一输入、目标与任务集。先采集离线影子结果：模型给出判断，用户操作不由模型自动改变。分别统计局部正确率、拒答与升级、重复运行稳定性和最终任务状态。不要用多数模型赞同当作事实金标准。

校准集与最终留出集分离。模型选择阈值随任务和版本登记；不能因为原型中使用0.70便把它当通用标准。比较结果不清晰时保留更简单实现，并记录未获得增益。
